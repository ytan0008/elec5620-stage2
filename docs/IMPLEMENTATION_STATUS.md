# Stage 1 to Stage 2 implementation status

Source: `ELEC5620_Wed_09-11 Group3.pdf`, especially the use case specifications on pages 25–37 and the UC9 states on page 47. The implementation follows the four agent roles (Learning Coordinator, AI Tutor, Assessment & Analytics, Quality Manager) and the human instructor. Stage 1 assumes calibrated model confidence; this system treats confidence as an uncalibrated self-report. TOEFL uses the January 2026 1–6 section scale.

The system runs in two engine modes. **REAL**: an OpenAI-compatible model (configured with `OPENAI_API_KEY`, optional `OPENAI_BASE_URL`) generates conversation, examiner follow-ups, new tests and rubric feedback, with optional cloud speech. **LOCAL** (no key): a curated exam-format test bank, a rule-based rubric analyser, a scripted examiner, a rule-based tutor and a bundled ECDICT dictionary subset. Every generated result passes the same quality gate in both modes. The default cloud model is `gpt-6-luna` (Responses API; reasoning effort none for conversation, low for scoring). Each agent has its own memory (`agent_memories`) and a tool set for its module, chosen by the model in a bounded tool-calling loop; tool calls and memories are visible in the teacher console. Fine-tuning is not used.

| UC5 Mock | Short (~90 min) or full-length (~2 h 45 min) computer-delivered mock: multi-speaker listening played once, three reading passages, both writing tasks, live speaking examiner; persistent timer, autosave, section scores and detailed review; dictionary and tutor locked server-side while running. The Assessment & Analytics agent prepares the mock (one retry, then "temporarily unavailable"), scores writing and speaking against the rubric (one retry; an unscored section holds the result for the teacher with the answers kept), names strengths and weaknesses against the target, compares with the previous mock and estimates readiness from the gap and trend. IELTS mocks run as on test day: the written test (Listening, Reading, Writing) in order, each section on its own clock with no going back, and the speaking test as a separate session before or after it, finished the same day; TOEFL keeps one sitting. A mock needs one verified practice result first. As in the real test, blank listening, reading or writing answers do not stop marking (they count as wrong, with a reminder before submitting); only a mock ended or abandoned before the speaking test is recorded as incomplete with no result, and one that runs out of time after the speaking test is marked; a verified mock automatically generates the full performance report (UC6), linked from the result page as "View full report"; a marked mock triggers UC7 adaptation. A held mock with an unscored section (5a) can only be released once the teacher supplies the missing score, which recalculates the overall band; a mock the teacher releases then gets the same follow-up as a verified one (report, Mistake book entries and UC7 adaptation) | Validated band conversion against official papers; inter-rater reliability measurement |
| UC6 Reports | Verified-only skill charts and history, weak/strong skills, repeated issues, saved quality-checked reports, knowledge graph overlay; notebook statistics showing which question types and grammar issues recur. The Assessment & Analytics agent analyses progress (one retry) and writes the report: strengths at or above the target and weaknesses below it never overlap, per-skill trends (improving, steady, declining, or "not enough data"), one readiness rule for the page and saved reports, recommendations from gaps, declining skills and repeated problems; if recommendations fail the report is kept without them; unavailable data shows a retry message, and a report page that cannot be shown says the report is currently unavailable, keeps the data and offers Try again (8a); "Recommended for me" opens UC10. Each report has its own page with a section-by-section diagnosis: listening and reading accuracy by question type and every missed question (not written, misspelled or wrong, with the correct answer); writing and speaking criteria against the target, grammar mistakes grouped by type with the original sentence and correction, vocabulary range and repetition, task problems, better versions of sentences and (speaking) pace, fillers and answer length; plus patterns across all practice | Predictive calibration; concept-level mastery; the live progress page is not quality-checked (saved reports are) |
| UC7 Adaptation | Three triggers share one flow (`backend/adaptation.py`): learner request, weekly review and a completed mock exam (UC5). 3a: fewer than two verified assessments keeps the plan and tells the learner. The proposal compares the active plan with verified scores and lists each major change (priority, weekly minutes) with its own rationale; the changes are computed, the model supplies the wording. 4a: one retry, then the existing plan is kept and the learner is told. 5/5a: one study resource per top priority, or the area shown without a recommendation. 6a/7a: change requests and rejection keep the existing plan. 8/8a: confirming activates the plan and delivers the new priorities to the AI Tutor and Assessment & Analytics; a failed delivery is logged, retried and never rolls the plan back | Deployed scheduler; a revised plan (6a) does not carry per-change rationales; notifications are in-process memory writes, not an external channel |
| UC8 Human review | Review queue (`backend/escalation.py`). Escalating notifies the instructor; with every instructor away (2a) the case is queued and released to the next one who marks themself available. Opening a case shows the learner's earlier results, previous decisions and highlights (low-confidence values and conflicting results, step 4). 3a: the Quality Manager gathers more evidence while the case stays open. Approve, override (corrected result) or request more information (5c, case stays open). One case history holds system events and each decision with its reasoning. The outcome is delivered to the relevant agents (Quality Manager plus the Tutor, Coordinator or Assessment agent by result kind); 7a: a failed delivery is logged and retried (retry button and the scheduled job) and the case stays resolved. Teacher developer console with live agent trace, anomaly detection (model failures, provider outages, holds, latency, score drops, curriculum gaps, inactivity) and learner issue reports with replies | Multi-instructor assignment (every available instructor is notified, and any of them can decide); notifications are in-app and in-process, not email or push; instructor availability is a manual toggle |
| UC9 Quality | Structured, threshold, rubric-key, score-range and consistency checks; generated tests must have every completion answer supported by the script/passage; durable hold/release; adjustable threshold with audit. 2a: an incomplete result is regenerated once, then held. 4a: the LLM consistency verdict is retried once, then the rule-based checks decide (a REAL-mode result that could not be checked is held) | Empirical false positive/negative rates |
| UC10 Materials | Strategy lessons per skill, filters, relevance feedback, quality-checked recommendations; structured question bank (IELTS listening parts, reading passages, writing tasks, speaking tests, TOEFL 2026 set), AI task generation, official sample links | Licensed official content |

Learning support added beyond Stage 1: an AI tutor with long-term memory (facts, goals, difficulties, verified progress, editable by the learner) and "Coach me" plans; a Mistake book (wrong answers by question type, retry and spaced review), Word book (select any word or tell the tutor; offline phonetics and Chinese meanings; flashcards and chat quizzes), Grammar book (feedback errors with combined corrections) and Sentence book (rewrites and saved sentences tagged by structure). During tests a selected word can be saved but its meaning stays hidden until the test ends.
